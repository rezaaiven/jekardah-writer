# Usage Patterns

## Ordinary Output

For direct adaptation requests, return the adapted text first. Keep notes short unless the draft risks performed casualness, lost qualifiers, or register mismatch for the platform.

## Sample Tasks

- Make a LinkedIn article sound like a person wrote it without losing the technical precision.
- Turn an article's summary into a short companion LinkedIn post.
- Convert a written section into a spoken script for a 60-second video.
- Convert an article into a long-form YouTube script outline in spoken register.
- Review whether a draft's casual tone reads as forced.
- Create variants: linkedin-article, linkedin-post, video-script.

## Register And Semantics

- Thought leadership keeps a visible opinion; hedges that only soften confidence go, hedges that mark evidence limits stay.
- Technical content keeps every term, number, version, and name exact; the conversational layer lives between the terms.
- Spoken registers get shorter clauses and said-aloud numbers; written registers may keep denser sentences where they scan.
- A companion post teases one idea; it does not compress the whole article.
- Casualness is subtraction (hedges, filler, formality), not addition (slang, emoji, exclamation marks).

## Review Checklist

- Is the target register named?
- Would the author plausibly say these sentences out loud?
- Did any qualifier that protected accuracy get deleted?
- Did any claim get stronger than the source supports?
- Are technical terms, numbers, names, links, and CTA intent untouched?
- For spoken registers: does every sentence survive being read aloud in one breath?
- Does the casual tone read as natural rather than performed?

## Output Patterns

- Direct request: adapted text first.
- Variants: label each register.
- Review: point out hedging, robotic cadence, performed casualness, and platform mismatch.
- Orchestrated use: style-layer changes only; return conflicts to the orchestrator instead of resolving them by changing meaning.
